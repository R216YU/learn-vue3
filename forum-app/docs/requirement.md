# 掲示板アプリ 要件定義書 (requirement.md)

## 0. このドキュメントについて

- このドキュメントは、学習用に作る「掲示板アプリ」の **仕様の正** です
- 実装は開発者自身が行い、完成後に AI がこのドキュメントと突き合わせてレビューします
- 仕様を変更したくなった場合は、実装を変えるだけでなく **このファイルも更新** してください

---

## 1. アプリの概要

ひとことで言うと「**スレッドを立てて、そこに書き込みができる掲示板**」です。

- ユーザーはスレッド（話題）を作成できる
- 作成されたスレッドに対して、誰でも投稿（レス）ができる
- ログイン機能はなく、投稿のたびに名前を入力する（未入力なら「名無しさん」）
- データはブラウザの localStorage に保存し、リロードしても消えない

## 3. 用語とデータモデル

### 3.1 用語

- **スレッド (Thread)**: 話題のまとまり。タイトルを持つ
- **投稿 (Post)**: スレッドの中に並ぶ書き込み。本文を持つ

### 3.2 型定義

```ts
// スレッド
type Thread = {
  id: string          // 一意なID（例: crypto.randomUUID()）
  title: string       // スレッドのタイトル
  createdAt: number   // 作成日時（Date.now() のミリ秒）
}

// 投稿
type Post = {
  id: string          // 一意なID
  threadId: string    // どのスレッドに属するか
  authorName: string  // 投稿者名（未入力なら "名無しさん"）
  body: string        // 本文
  createdAt: number   // 投稿日時
}
```

### 3.3 データの持ち方

- `Thread[]` と `Post[]` を **フラットな配列で別々に** 持つ
  （`Thread` の中に `posts` をネストさせない）
- スレッドの投稿数や最終投稿日時は、保存するのではなく **`Post[]` から計算して求める**

### 3.4 localStorage

- キーは `forum-app:threads` / `forum-app:posts` のように接頭辞をつける
- 読み込み時に JSON.parse が失敗する / 中身が壊れている可能性を考慮し、
  失敗したら空配列にフォールバックしてアプリが落ちないようにする

## 4. 画面（ルーティング）

| パス | 画面名 | 内容 |
| --- | --- | --- |
| `/` | スレッド一覧 | スレッドの一覧と、新規スレッド作成への導線 |
| `/threads/new` | スレッド作成 | 新しいスレッドを立てるフォーム |
| `/threads/:id` | スレッド詳細 | そのスレッドの投稿一覧と投稿フォーム |
| 上記以外 | Not Found | 「ページが見つかりません」＋一覧へ戻るリンク |

## 5. 機能要件

### 5.1 スレッド一覧画面 (`/`)

- [ ] 登録済みスレッドを一覧表示する
- [ ] 各行に表示する情報
  - タイトル
  - 投稿数
  - 最終投稿日時（投稿が0件ならスレッド作成日時）
- [ ] 並び順は **最終投稿日時の新しい順**
- [ ] タイトル部分をクリックするとスレッド詳細へ遷移する
- [ ] キーワード入力欄があり、**タイトルの部分一致**で絞り込める（大文字小文字は区別しない）
- [ ] スレッドが 0 件のとき、および検索結果が 0 件のときは、それぞれ空状態のメッセージを表示する
- [ ] 「スレッドを作成」ボタンから `/threads/new` へ遷移できる

### 5.2 スレッド作成画面 (`/threads/new`)

- [ ] 入力項目
  - スレッドタイトル（必須 / 1〜50文字）
  - 投稿者名（任意 / 最大20文字 / 未入力なら「名無しさん」）
  - 最初の本文（必須 / 1〜500文字）
- [ ] 作成ボタンを押すと、スレッドと **最初の投稿を1件** 同時に作成する
- [ ] 作成後は、作成したスレッドの詳細画面へ遷移する
- [ ] バリデーションエラーがある間は作成ボタンを押せない、またはエラーメッセージを表示する
- [ ] キャンセルで一覧へ戻れる

### 5.3 スレッド詳細画面 (`/threads/:id`)

- [ ] スレッドタイトルを表示する
- [ ] そのスレッドに属する投稿を **古い順** に一覧表示する
- [ ] 各投稿に表示する情報
  - 連番（1, 2, 3...  スレッド内での通し番号）
  - 投稿者名
  - 投稿日時
  - 本文（改行が入力どおりに表示されること）
- [ ] 画面下部に投稿フォームがある
  - 投稿者名（任意 / 最大20文字）
  - 本文（必須 / 1〜500文字）
- [ ] 投稿するとその場で一覧に追加され、入力欄がクリアされる
- [ ] 各投稿に削除ボタンがあり、確認ダイアログの後に削除できる
- [ ] 一覧画面へ戻るリンクがある
- [ ] URL の `:id` に対応するスレッドが存在しない場合は「スレッドが見つかりません」を表示する

### 5.4 共通

- [ ] 日時は `2026/09/22 14:30` のような読みやすい形式で表示する
- [ ] 入力値は前後の空白をトリムしてから保存・バリデーションする
- [ ] 空白のみの入力は「未入力」として扱う

## 6. やらないこと（スコープ外）

以下は今回の学習範囲では **実装しない**。

- ログイン / 認証 / ユーザー管理
- サーバー通信（バックエンドAPI）
- スレッドや投稿の編集機能
- ページネーション、無限スクロール
- 画像・ファイルのアップロード
- いいね、通知、検索の全文検索対応
- ダークモード等のテーマ切り替え

## 7. 設計方針（構成の目安）

厳密な指定ではなく目安です。迷ったらこの形に寄せてください。

```
src/
├── components/     # 表示に責務を持つコンポーネント（ThreadListItem.vue など）
├── composables/    # 状態とロジック（useThreads.ts / usePosts.ts など）
├── core/           # Vueに依存しない純粋なロジック（storage.ts / format.ts など）
├── router/         # ルーティング定義
├── types/          # 型定義
├── views/          # 各ルートに対応する画面（ThreadListView.vue など）
├── App.vue
└── main.ts
```

意識したいこと:

- **views は「画面の組み立て」、components は「部品」** として役割を分ける
- データの取得・更新ロジックはコンポーネントに直接書かず composable に寄せる
- 親から子へは props、子から親へは emit の流れを守る
- localStorage 操作や日付フォーマットなど、Vue に依存しない処理は `core/` に置いて単体で考えられるようにする

## 8. 完成の判断基準（レビュー時のチェックに使う）

1. 5章のチェックボックスがすべて満たされている
2. リロードしてもスレッドと投稿が消えない
3. 存在しないURLを直接開いてもアプリがクラッシュしない
4. `npm run build`（型チェック含む）が通る
5. Vue3 のベストプラクティスに沿っている（詳細は CLAUDE.md のレビュー観点を参照）
